# Pilot Evidence Ledger

The Pilot Evidence Ledger gives MajlisAlpha a simple place to capture proof while the pilot conversation is still fresh. It exists because useful pilot evidence often arrives in small pieces: a real question, an official-source concern, a second use case, a shareable output, a follow-up action, or a pricing signal. If those signals are not saved immediately, the Pilot Value Proof Center can look weaker than the pilot really is.

Use the ledger after a demo, call, WhatsApp reply, source review, or desk answer. Save one entry per proof item and choose the lane that best describes it:

- Use case: the painful UAE market question or workflow the user brought.
- Source proof: official disclosure, annual report, exchange update, or source-review confidence.
- Repeat proof: second question, return visit, or request for another answer.
- Output proof: PDF, Markdown brief, memo packet, or committee artifact.
- Workflow proof: review decision, follow-up, outreach, next date, or owner.
- Revenue proof: AED pilot intent, pricing discussion, invoice path, team plan, or close probability.

## Operating Workflow

1. Run or review the pilot interaction.
2. Open the Pilot Evidence Ledger.
3. Use desk context when a current answer exists, or write the proof manually.
4. Mark the status as captured, verified, or needs proof.
5. Set impact conservatively; verified source or paid-pilot evidence should score higher than early interest.
6. Save the entry and return to the Pilot Value Proof Center.

The ledger is local-browser storage. It is useful for product and founder operating decisions, not for making investment recommendations. Before using an entry in an external memo or sales note, confirm that customer claims, source references, and pricing signals are accurate.
