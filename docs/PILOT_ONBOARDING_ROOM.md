# Pilot Onboarding Room

The Pilot Onboarding Room turns a successful MajlisAlpha demo into a named pilot account workflow. It is designed for the moment after a user says the product is useful, when the next step should become specific: who is the account, what was the first real UAE market question, which source proof is required, what trust objection was captured, when is the follow-up, and whether pricing should enter the conversation.

Use this room after the Pilot Demo Script Center, Pilot Learning Loop Center, and Founder Weekly Review Center. The onboarding room reads the current browser session, including pilot sessions, follow-ups, outreach drafts, conversion records, current answer context, source-pack imports, memo reviews, and deployment health. It then produces an activation score, cards for the onboarding path, and a ranked set of next actions.

Recommended operating flow:

1. Run or review the demo script and capture one real user question.
2. Save a Pilot Session with source status, objection, paid-intent signal, and next step.
3. Add one official source when the answer is still starter-only or synthetic-heavy.
4. Use the onboarding room to prefill the Follow-Up Board.
5. Send the exported brief and ask for a second real UAE question.
6. Move paid-intent accounts into Outreach Composer and Conversion Pipeline.
7. Roll the result into Founder Weekly Review before the next build.

The onboarding room is deliberately practical. It does not ask the founder to admire the product; it asks whether the product has a named account, a real use case, a trust path, and a next commercial move. If any of those are missing, the primary action button opens the most relevant workflow.

Treat exported onboarding plans as internal operating notes. Remove private names, phone numbers, email addresses, or sensitive account details before sharing outside the project. MajlisAlpha is research software and workflow tooling, not investment advice.
